# Оверлей Desktop: замеры кандидатов (MVP-0, S0.2)

Статус: основа для [ADR-0021](../adr/0021-desktop-rendering-stack.md). Замер от 2026-11-04 на
Windows 11. Сырые результаты — в [overlay/](overlay/).

## Сценарий

Прототипы лежат в `prototypes/`. Оба рисуют одного и того же голубя из примитивов (общий код в
`Overlay.Shared`) в маленьком окне 96×96 логических пикселей, которое движется вслед за голубем.
Голубь ходит по нижней кромке рабочей области и перелетает дугой, в том числе на другой монитор,
если он есть. Окно прозрачное, поверх всех, не забирает фокус, не видно в Alt-Tab. Клики проходят
сквозь окно везде, кроме голубя.

Автозамер (`--measure out.json`): разогрев 3 с, покой 15 с (голубь сидит, 10 кадров в секунду),
движение 15 с (60 кадров в секунду по расписанию поверх синхронизации с экраном). Проверки
попадания делаются через `WindowFromPoint` в центр голубя и в прозрачный угол окна.

**Эталонная машина:** Intel Core Ultra 7 258V (8 ядер), 32 ГБ, Intel Arc 140V, встроенный экран
2560×1600, 144 Гц, масштаб 175 %, Windows 11 (сборка 28000). Один монитор.

## Кандидаты

- **A. Avalonia 12.1.4.** Окно без рамки с `TransparencyLevelHint = Transparent`, стили
  no-activate и tool window — через Win32. Прозрачное окно Avalonia забирает клики всей площадью,
  поэтому click-through переключается флагом `WS_EX_TRANSPARENT` по положению курсора: таймер
  60 Гц сравнивает курсор с силуэтом голубя.
- **B. Своё Win32-окно + SkiaSharp 3.119.4.** Layered-окно (`WS_EX_LAYERED`), SkiaSharp рисует в
  DIB-секцию, вывод — `UpdateLayeredWindow` с попиксельной альфой. Прозрачные пиксели система
  пропускает для кликов сама.
- **C. SDL3 / GLFW** — не делали. Layer-shell у них нет, а это главный Linux-путь. По Windows
  кандидат B уже показал, что тонкий слой окна прост.

## Результаты

| Показатель | A. Avalonia | B. Win32 + SkiaSharp |
|------------|------------:|---------------------:|
| Время до первого кадра | 1.07–1.66 с | 0.15 с |
| CPU в покое (10 кадров/с), % одного ядра | 14–17 | 2.4–3.2 |
| CPU в движении (60 кадров/с), % одного ядра | 39–44 | 12.4 |
| Память, working set | ~137–144 МБ | ~31–33 МБ |
| Private bytes | ~78 МБ | ~10–12 МБ |
| Кадров в секунду в движении | 58–59 | 59.4 |
| Кадров дольше 25 мс за 15 с движения | 222–263 | 46 |
| Клик по голубю попадает в окно | ✅ | ✅ |
| Клик мимо проходит сквозь окно | ✅, переключением по курсору | ✅, попиксельно |
| Поверх всех, без фокуса, нет в Alt-Tab | ✅ | ✅ |

**Против бюджетов ТЗ §37** (они заданы в процентах от всего CPU, на эталонной машине 8 ядер):

| Бюджет §37 | Цель | A. Avalonia | B. Win32 + SkiaSharp |
|------------|------|------------:|---------------------:|
| CPU, голубь сидит | ≤ 0.5 % | 1.8–2.1 % ❌ | 0.3–0.4 % ✅ |
| CPU, голубь в движении | ≤ 2 % | 4.9–5.5 % ❌ | 1.6 % ✅ |
| RAM (working set) | ≤ 150 МБ | 137–144 МБ ⚠️ — почти весь бюджет на одно окно | 31–33 МБ ✅ |
| Старт до первого кадра | ≤ 3 с | 1.1–1.7 с ✅ | 0.15 с ✅ |

Диапазоны — по 2–3 прогонам. Кадры дольше 25 мс на экране 144 Гц есть у обоих: 60 Гц не делится
на 144 Гц, и часть кадров ждёт лишнюю синхронизацию. Сравнивать их стоит только между собой.

## Выводы

1. **B в 3–5 раз экономнее по CPU и в 4 раза по памяти, стартует в 7–10 раз быстрее.** Для
   питомца, который висит на экране весь день, это главное. B укладывается в бюджеты ТЗ §37 с
   запасом, A выходит за бюджет CPU в 3–4 раза, а одно окно Avalonia съедает почти весь бюджет
   памяти.
2. **Click-through в B честный, попиксельный, без опроса курсора.** В A он держится на таймере
   60 Гц и переключении стиля окна. Это лишняя работа, и есть окно гонки: курсор быстро въехал в
   голубя, а стиль ещё не переключён.
3. **В покое A тратит 14–17 % одного ядра**, даже когда цикл кадров остановлен. Причина не
   выяснена: вероятно, собственный конвейер композиции Avalonia и таймер опроса курсора. Глубже не
   копали: B лучше и без этого.
4. **Цена B — платформенный код окна на каждую ОС.** На Windows это ~250 строк. Для macOS
   (`NSPanel`), X11 (ARGB-visual + XShape) и Wayland (layer-shell) будет столько же, а
   отрисовка SkiaSharp общая.

## Что ещё не проверено

- **Два монитора с разным масштабом** — переход голубя между ними и `WM_DPICHANGED`. Код
  перелёта на другой монитор есть, проверка — после подключения второго монитора.
- **macOS, X11, Wayland** — окна для этих ОС ещё не написаны (MVP-1). Ожидаемые механизмы — в
  [матрице возможностей](../platform/capability-matrix.md).
- **Окно настроек** — может быть на Avalonia независимо от оверлея. Тогда память Avalonia
  платится только при открытых настройках.
