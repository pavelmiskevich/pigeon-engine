# Матрица возможностей платформ и уровни деградации Desktop

Статус: **Accepted** (ADR-0011). Значения в таблицах — ожидания по документации платформ;
каждая ячейка подтверждается или исправляется в MVP-0 (задача S0.3, утилита `pigeon-probe`).
Пока ячейка не проверена, она помечена `?` в столбце «Проверено».

Связанные документы: [ТЗ §11–13](../spec/PIGEON_Technical_Specification.md#11-desktop-world),
[MVP-0](../roadmap/mvp-0.md), [ADR-0011](../adr/0011-platform-capability-matrix.md).

---

## 1. Зачем это нужно

Главная механика Desktop — голубь живёт в *реальном* рабочем столе: сидит на окнах, следит
за курсором, перелетает между мониторами. Эти возможности на платформах не равны:

- Windows и Linux X11 отдают почти всё: геометрию чужих окон, z-order, глобальный курсор.
- macOS отдаёт геометрию и курсор, но заголовки окон — только с разрешением Screen Recording,
  а события перемещения чужих окон — только через Accessibility.
- Wayland намеренно запрещает приложению знать позиции чужих окон и глобальный курсор, а на
  GNOME клиент даже не может сам сделать окно «поверх всех».

Если это не зафиксировать, код начнёт подделывать отсутствующие данные (что прямо запрещено
ADR-0002) или ломаться на части платформ. Поэтому:

1. Движок работает не с «платформой», а с **набором возможностей** (capabilities), который
   определяется при запуске пробой (`ICapabilityProbe`).
2. По набору возможностей выбирается **уровень Desktop-опыта** (L0–L3).
3. Поведение, которому нужна отсутствующая возможность, **не выбирается** Utility AI
   (оценка = 0). Отсутствующие данные никогда не имитируются.

## 2. Каталог возможностей

### Ожидаемые механизмы и примечания

**Windows** (Win32; минимальная версия — та, что поддерживает .NET 10).
- C1/C2: layered-окно с попиксельной альфой (`WS_EX_LAYERED` + `UpdateLayeredWindow` либо
  DirectComposition); полностью прозрачные пиксели пропускают клики. Запасной путь —
  переключение `WS_EX_TRANSPARENT` по попаданию курсора в хитбокс голубя.
- C3/C4: `HWND_TOPMOST`, `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW`.
- C5/C6: `EnumDisplayMonitors`, `GetDpiForMonitor`, Per-Monitor DPI Awareness V2,
  `WM_DISPLAYCHANGE`, `WM_DPICHANGED`.
- C7: `GetCursorPos` с адаптивной частотой опроса. Глобальные low-level хуки мыши не использовать.
- C8/C9: `EnumWindows` (порядок = z-order), `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`,
  фильтр `DWMWA_CLOAKED` (окна других виртуальных столов, «спящие» UWP).
- C10: `SetWinEventHook` (out-of-context): `EVENT_OBJECT_LOCATIONCHANGE`, `EVENT_SYSTEM_FOREGROUND`,
  `EVENT_OBJECT_SHOW/HIDE/DESTROY`, `EVENT_SYSTEM_MINIMIZESTART/END`.
- C11/C12: `GetForegroundWindow` → PID → имя исполняемого файла; `GetWindowText` технически
  доступен без разрешений, но читается только при включённой capability `Window` (§14 ТЗ).
- C14: `SHQueryUserNotificationState` (presentation, D3D fullscreen, busy) + сравнение
  геометрии окна переднего плана с монитором.
- (13) C15: `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`, начиная с Windows 10 2004.
- C16/C17: `GetLastInputInfo`, `WM_POWERBROADCAST`, `WTSRegisterSessionNotification`.
- (17) C20: окно по умолчанию принадлежит одному виртуальному столу; закрепление на всех —
  через недокументированный API. Проверить, как ведёт себя `WS_EX_TOOLWINDOW` + topmost.

**macOS** (минимальная версия — та, что поддерживает .NET 10; уточнить в MVP-0).
- C1/C3/C4: `NSPanel` без рамки, `isOpaque = false`, `level = .floating`/`.statusBar`,
  non-activating, `LSUIElement` (нет иконки в Dock).
- (2) C2: `ignoresMouseEvents` действует на всё окно — нужно переключать его по попаданию
  курсора (`NSEvent.mouseLocation`) в хитбокс голубя с частотой ~30–60 Гц, пока курсор рядом.
- C7: `NSEvent.mouseLocation` без разрешений.
- C8/C9: `CGWindowListCopyWindowInfo` — bounds, layer, PID владельца, порядок front-to-back —
  без разрешений.
- (10) C10: push-события чужих окон только через `AXObserver` (разрешение Accessibility).
  По умолчанию — опрос `CGWindowList` с адаптивной частотой (часто, пока голубь сидит на окне;
  редко в остальное время).
- (12) C12: `kCGWindowName` отдаётся только при разрешении Screen Recording. Мы его **не
  запрашиваем** — заголовки на macOS по умолчанию недоступны, что совпадает с политикой §14.
- C13: `NSScreen.visibleFrame` (меню-бар и Dock); Dock с автоскрытием — ⚠️.
- C14: полноэкранные приложения живут в отдельном Space — определять по геометрии и
  активному приложению; ⚠️.
- (14) C15: `NSWindow.sharingType = .none`; в новых версиях macOS захват через ScreenCaptureKit
  может это игнорировать — проверить.
- C16: `CGEventSourceSecondsSinceLastEventType`; C17: уведомления `NSWorkspace`.
- C19: `SMAppService`. C20: `collectionBehavior = [.canJoinAllSpaces, .stationary]`.
- Дистрибуция: обязательны подпись Developer ID, hardened runtime и нотаризация.

**Linux X11** (EWMH-совместимый оконный менеджер).
- (1) C1: ARGB-visual работает только при запущенном композиторе. Без композитора — уровень L1.
- C2: XShape input region (`XFixesSetWindowShapeRegion`, `ShapeInput`).
- (3) C3: `_NET_WM_STATE_ABOVE` — выполнение зависит от оконного менеджера.
- C4: `_NET_WM_WINDOW_TYPE_UTILITY`, `_NET_WM_STATE_SKIP_TASKBAR/SKIP_PAGER`, input hint = false.
- (6) C5: XRandR даёт геометрию, но в X11 нет честного DPI для каждого монитора — масштаб
  глобальный (`Xft.dpi`).
- C7: `XQueryPointer`. C8/C9: `_NET_CLIENT_LIST_STACKING`, `_NET_FRAME_EXTENTS`,
  `XTranslateCoordinates`. C10: `ConfigureNotify`/`PropertyNotify`.
- C11/C12: `_NET_ACTIVE_WINDOW`, `_NET_WM_PID`, `_NET_WM_NAME`. C13: `_NET_WORKAREA`, struts.
- C14: `_NET_WM_STATE_FULLSCREEN`. C15: механизма нет.
- C16: расширение XScreenSaver. C17: logind (D-Bus, `PrepareForSleep`).
- C20: `_NET_WM_DESKTOP = 0xFFFFFFFF`.

**Wayland: KDE Plasma и композиторы на wlroots** (Sway, Hyprland и т. п.).
- (4) C3: `zwlr_layer_shell_v1`, слой `overlay`, по поверхности на каждый выход.
  Поддерживается KWin и wlroots, **не поддерживается Mutter (GNOME)**.
- C2: `wl_surface.set_input_region` — только хитбокс голубя.
- (7) C7: глобального курсора в протоколе нет. Позиция известна, только пока курсор над нашей
  input region, то есть над самим голубем. Реакции «на расстоянии» недоступны.
- (8) C8–C10: протокол Wayland геометрию чужих окон не отдаёт. На KDE возможен обходной путь
  через скрипт KWin и D-Bus — это отдельная опциональная интеграция, не в MVP.
- (11) C11/C12/C14: `wlr-foreign-toplevel-management` (wlroots) или
  `org_kde_plasma_window_management` (KDE) дают app_id, заголовок и состояния
  activated/fullscreen, **без геометрии**.
- (15) C16: `ext-idle-notify-v1` там, где он есть, иначе D-Bus композитора.
- (16) C18: Secret Service (libsecret); если keyring-демона нет — ⚠️, fallback на
  зашифрованный файл с явным предупреждением.

**Wayland: GNOME (Mutter).**
- (5) C3: layer-shell нет, клиент не может сам встать поверх всех окон.
- (9) C7–C14: без расширения GNOME Shell данные недоступны. Расширение Shell — отдельный
  продукт на JavaScript со своим циклом ревью, в MVP не входит.
- Частичный обходной путь — запуск под XWayland. Тогда видны только X11-клиенты, курсор
  известен только над X11-окнами, поддержка `_NET_WM_STATE_ABOVE` зависит от Mutter. Проверить
  в MVP-0, в продукте включать только если результат приемлем.

**Общие особые случаи** (проверяются на всех платформах):
- RDP/VNC и виртуальные машины: смена DPI и топологии при подключении и отключении сессии.
- Смешанный DPI: координаты окон и мониторов переводятся в единое пространство
  (физические пиксели), при выводе делятся на scale монитора.
- Мониторы с зазорами и разной высотой: объединение прямоугольников — не прямоугольник.
- Эксклюзивный полноэкранный режим игр: оверлей не виден и не должен пытаться быть видимым.

## 4. Уровни Desktop-опыта (деградация)

Уровень вычисляется при запуске и пересчитывается при изменении окружения (смена сессии,
падение композитора, отзыв разрешения). Текущий уровень и отсутствующие возможности видны в
настройках и в Developer Mode.

| Уровень | Название | Нужно | Что доступно | Что недоступно |
|---------|----------|-------|--------------|----------------|
| **L3** | Full Desktop World | C1–C5, C7, C8, C9 | Всё из ТЗ: насесты на окнах с учётом окклюзии, следование за окном, реакции на курсор на расстоянии, Application Awareness (при C11) | — |
| **L2** | Screen World | C1–C5 | Голубь живёт на поверхностях экрана: нижняя кромка work area, taskbar/Dock/панели (при C13), края и границы мониторов, перелёты между мониторами. Взаимодействие — когда курсор над голубем (гладить, тащить, тыкать). При C7 — полноценные реакции на курсор | Насесты на окнах, окклюзия, WindowMoved/WindowOpened |
| **L1** | Window Mode («вольер») | C1 или обычное окно | Голубь живёт в обычном окне, которое пользователь двигает и растягивает. Мир = окно и его края. Симуляция, память, отношения, Life Story — полностью | Жизнь поверх рабочего стола |
| **L0** | Background | — | Отрисовки нет (экран заблокирован, RDP отключён, рендер недоступен). Симуляция идёт с редким тиком, события пишутся в журнал | Визуальная часть |

Отдельные возможности **поверх** уровня включают или выключают конкретные функции независимо:
C7 → курсор на расстоянии; C11 → Application Awareness; C14 → автоматический режим тишины;
C15 → исключение из захвата экрана; C10 → следование за окном без опроса.

### Ожидаемый уровень по платформам

| Платформа | Ожидаемый уровень | Комментарий |
|-----------|-------------------|-------------|
| Windows 10/11 | **L3** | Эталонная платформа |
| macOS | **L3** | Без заголовков окон; следование за окном — опросом |
| Linux X11 + композитор | **L3** | Без композитора — L1 |
| Wayland KDE / wlroots | **L2** | Без глобального курсора. L3 возможен позже через интеграцию с KWin |
| Wayland GNOME | **L1** | L2 возможен позже через расширение GNOME Shell; XWayland — исследовать в MVP-0 |

### Правила для кода

1. Любая функция, зависящая от возможности, проверяет её через `WorldCapabilities`, а не по
   типу ОС (`OperatingSystem.IsWindows()` допустим только внутри платформенного адаптера).
2. Отсутствующая возможность → соответствующие affordances не публикуются, намерения получают
   оценку 0. Никаких «примерных» окон или курсоров (ADR-0002).
3. Потеря возможности на лету (окно-насест исчезло, композитор упал) — это доменное событие.
   Голубь на него реагирует (вспорхнул, перелетел), а не телепортируется.
4. Каждая поддерживаемая комбинация «платформа × уровень» имеет автотест на уровне адаптера
   (с фейковым источником данных) и ручной сценарий проверки.

## 5. Утилита `pigeon-probe`

Часть MVP-0 (S0.3). Консольное приложение, которое:

- определяет все возможности C1–C20 и итоговый уровень;
- выводит отчёт (текст и JSON): ОС, версия, сессия (X11/Wayland/композитор), мониторы и DPI,
  найденные окна (**без заголовков**, если не передан явный флаг);
- используется для заполнения столбца «Проверено» и для баг-репортов пользователей.
